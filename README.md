# Rimworld PackFrame

Avalonia 12 写得环世界整合包管理器。优点就是多实例共存（比MO2还方便）、自动排序、便携化、我自己做的整合包安装。

## 快速开始（我写的）

1. 点右边的release，最新的Windows64，下载，随便哪个路径（空间要大一点，本地mod会放实例本身里），解压。
2. 双击根目录 `Rimworld PackFrame.exe`。
3. 首次启动选择语言，自动检测 RimWorld 游戏目录。
4. 在实例菜单中新建、复制或导入实例，也可以打开合集窗口安装整合包。
5. 编辑启用列表后点击“保存”，再启动游戏。Steam 工坊内容需要等待 Steam 完成下载。

支持 中英简繁和家乡话。

## 功能（我写的）

- 打开之后点那个在右侧展开，能打开另一列列表，点击可以切换启动的列表，两个列表之间拖mod是复制模组。
- 不同实例在列表顶部下拉栏切换，推荐一上来就把官方路径复制备份一下，本地mod也搬到复制出来的实例根路径下（\ProfileX\Mods没有Mods文件夹自己创）
- 自动排序功能不会调整大多数mod的排序，不用怕随便点，
- 有分类和涂色功能，再点一次取消工具选择，清除标记的工具也是在里面选。
- 有撤销功能，随便乱点就完事了，点坏了加群告诉我。
- 左边详情栏有备注和直接填的分类栏。
- 合集页面点进去选一个，然后翻到最下面，点正版，然后等本地Tweak、config下载（修补模组和模组配置），最后是软件自动订阅创意工坊模组，这一步如果卡住可以自己去订阅那个合集。

## 功能（ai写的可以跳过）

- 左侧显示模组预览图、名称、作者、路径、Package ID 和简介。
- 最多三列列表：未启用模组、两个可选择实例的已启用列表；未启用列标明启用目标，目标栏的标题区域高亮。新用户默认显示一个已启用列表；点击其标题上的“在右侧打开”可增加同一实例的第二个视图，再从右栏选择其他实例。右栏可单独关闭，布局选择会保存。
- 两个已启用列表可分别选择实例；选择同一实例时显示“同一列表”。搜索、选择和滚动各自保留；在另一栏查找目标不会清除已选模组，键盘及菜单操作只作用于当前栏。
- 已启用模组以紧凑的编号列显示真实加载顺序；筛选不会重新编号，缺失模组会留下编号空位。状态标记位于行末，可悬停查看详情。拖拽预览标明移到哪个模组前后，或在目标实例中添加/重新排序，并显示落点；跨实例拖拽保留来源列表。启动按钮显示当前目标实例的名称。
- 搜索名称、作者、路径、Package ID 或支持版本；支持来源筛选、问题筛选和显示模式切换。
- 支持单选、多选、Shift 范围选择、Ctrl 逐项选择、跨列拖拽和排序、双击启用/禁用。
- 支持颜色标记、颜色标签、涂色操作、撤销/重做；历史保留最近 10 步。
- 显示排序、版本、重复与缺失模组信息。规则检查不等同于完整兼容性验证。
- 排序检查包含 `loadAfter`、`forceLoadAfter`、`loadBefore`、`forceLoadBefore`；启用的 `incompatibleWith` 关系会在 S 问题详情中明确显示，不作为可用排序解决的问题。
- 实例菜单支持新建、复制、重命名、删除、导入、导出和打开配置目录。
- 导入支持 ModsConfig XML、兼容的 JSON 模组列表、`.rml`、`.rws` 存档模组信息、实例 ZIP 和实例文件夹。

列表编辑暂存在内存，点击“保存”才写入 `ModsConfig.xml`。普通保存保留缺失模组项。刷新或关闭时如有未保存的列表修改，会提供“保存 / 丢弃 / 取消”。颜色标记独立写入颜色文件。

启动前会将磁盘配置中的 `activeMods` / `knownExpansions` 包名规范化为小写，以兼容旧配置；仅在需要修改时写入，并在同目录保留 `ModsConfig.xml.before-normalize-*.bak`。发现/浏览实例不会修改配置。

## 实例与数据目录（ai写的可以跳过）

```text
PackFrame/
  Rimworld PackFrame.exe             Windows 本地目录版入口
  app/PackFrame/                     源码
    bin/Release/net10.0/             本地目录版运行程序
      packframe.json                语言、游戏路径、实例选择等应用设置
      packframe.log                 启动器错误日志
  instance/
    ModColors.json                  模组颜色与标签
    profile1/
      Config/                       模组排序与游戏/模组设置
        ModsConfig.xml
      Saves/                        存档
      Mods/                         此实例附带或 SteamCMD 下载的模组
      packframe.instance.json       显示名、来源、配置同步绑定、SteamCMD 标记
      player.log                    游戏日志
    profile2/
  Input profile/                    导入文件的默认位置
  Output profile/                   导出的实例或整合包文件
  tools/steamcmd/                    自动安装的 SteamCMD（使用时生成）
  runtime/                          整合包安装暂存目录
  tests/PackFrame.Checks/            回归检查
```

`packframe.json` 和 `packframe.log` 始终位于实际托管程序目录；单文件发布版与其可执行文件同目录。错误日志超过约 2 MB 后轮换为 `packframe.log.1`。

实例用 `profileN` 文件夹编号；重命名只改变显示名，复制和重命名会保留整合包来源绑定。旧版 `profile/` 可用于首次实例迁移；当前版本不需要旧的 `tools/pack.ps1` 流程。

损坏的实例显示 `⚠`，悬停实例选择框可查看原因；其他实例仍可使用。损坏实例禁止列表编辑和启动，菜单保留打开目录、导入恢复、删除（普通实例）入口。修复文件后点击刷新重新加载。

## 游戏启动与隔离（ai写的可以跳过）

普通实例按以下方式启动：

```text
"<游戏可执行文件>" -logfile "<实例目录>/player.log" -savedatafolder=<实例目录>
```

实际参数通过 `ProcessStartInfo.ArgumentList` 传入，支持空格和中文路径。避免在实例路径中使用 `=`，游戏自身的参数解析可能无法正确处理。

`-savedatafolder` 隔离 Config、Saves、ModLists、Scenarios、Ideos 等运行数据。**“官方路径”实例直接使用所选原版配置目录，编辑和保存会作用于该目录**；普通实例则使用自己的目录。

扫描来源包括游戏 `Data`、游戏 `Mods`、Steam 工坊和实例 `Mods`。实例模组通过临时目录链接提供给游戏，正常退出后清理，下次启动前也会恢复遗留链接。

配置和存档隔离不等于游戏二进制及工坊版本隔离。Steam 仍可能自动更新工坊模组；需要固定游戏与模组版本时，应另行保留完整副本。

## 程序更新（ai写的可以跳过，每次打开记得的话点左下角更新就完事了）

点击主窗口的“检查更新”读取 GitHub 上已发布的正式版本。检查本身不会下载、安装或重启程序；发现新版后先显示版本和更新说明。

Windows 的兼容更新包可在程序内下载，下载后仍需单独点击“安装并重启”。可以稍后再安装，已校验的下载会保留。安装前会处理未保存的模组列表；取消会继续使用当前程序。RimWorld 运行期间可以查看或下载更新，安装需要先关闭游戏。

更新包按发布信息中的文件大小和 SHA256 校验，只替换程序文件，保留 `packframe.json`、实例、存档、模组与缓存。更新助手仅在用户选择安装、主窗口实际关闭后替换文件；应用失败时回滚并保留备份。下一次启动会显示更新结果。没有兼容更新包的平台可从发布页面手动更新。

更新使用已发布的 GitHub Release，不会拉取或执行 `main` 分支源码，也不需要用户安装 Git。维护者发布高于当前程序集版本的新版本及兼容的 ZIP 资产后，现有安装才能发现更新。

GitHub 不可用时会退到 Gitee 的 Release。Gitee 接口不提供资产哈希，所以校验值写在仓库的 `update/latest.json`（随版本提交），Release 里只放用户要下载的 ZIP。发版时更新该文件：`Version` 必须与 tag 一致（不带 `v`），`Name` 必须与 Release 资产同名，否则该平台不会提供自动更新。

## 文件管理（我写的）

- 实例文件夹 Instance：里面相当于Ludeon Studios\RimWorld by Ludeon Studios里的格式，有Saves和Mods。
- 实例Mods文件夹的启用是通过在你游戏根目录Mods文件夹创建符号链接实现的。
- 故障排查： `packframe.log` 在主界面日志按钮打开，与实例 `player.log` 在实例栏下方点那个三个点，点打开，再退一层文件夹（游戏需要退出，是从官方路径复制过来的。）
